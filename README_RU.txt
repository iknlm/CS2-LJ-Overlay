# CS2 LJ Overlay v1.2 - Windows x64

**IKNLM — основной автор, создатель и владелец проекта.**
Исходный код: **MIT © 2026 IKNLM**. [Авторство](AUTHORS.md) · [English](README_EN.md).
Claude, ChatGPT и Codex указаны исключительно как помощники разработки.

Автономный Windows x64 WinAPI/GDI HUD для статистики прыжков CS2 CYBERSHOKE.
Читает `game/csgo/console.log`, не внедряет DLL и не изменяет процесс игры.
Одно окно `LJOverlayWnd`, справа по умолчанию; темы Modern и CS 1.6.

## Скачать Windows x64

1. Скачайте [LJOverlay_v1.2_win64.zip](https://github.com/iknlm/CS2-LJ-Overlay/releases/download/v1.2/LJOverlay_v1.2_win64.zip).
2. Распакуйте архив.
3. Запустите `LJOverlay_new.exe`.
4. При необходимости настройте путь к `console.log`.

**Для обычного запуска компилятор, MSYS2 и Python не нужны.**
Сохраните `sounds/` рядом с EXE. Для первой установки используйте полный ZIP.
Отдельный EXE подходит для обновления уже распакованной программы.
Добавьте `-condebug` в параметры CS2, перезапустите игру
и используйте оконный или безрамочный режим.
Путь к логу: INS -> 9 -> 10 «Источник console.log».
Сборка нужна только разработчикам; см. [TESTING.md](TESTING.md).

## Управление

| Клавиша | Действие |
| --- | --- |
| INS | Открыть или закрыть настройки внутри HUD |
| F6 / F7 | Ручной GOOD / BAD последнего прыжка |
| F8 | Вернуть автоматическую оценку последнего прыжка |
| F9 | Закрепить HUD и включить пропуск кликов |
| Home | Скрыть или показать HUD |
| Ctrl+End | Завершить работу |
| PgUp / PgDn, колесо | Прокрутка выбранного раздела HUD |

Старую попытку можно отметить через INS -> История -> выбрать -> GOOD/BAD/авто.
Глобальные F6/F7/F8 всегда относятся к последней попытке.
Цифры работают только в открытых сфокусированных настройках.
Очистка сессии и перечитывание с заменой истории требуют подтверждения.
При открытых настройках HUD можно перемещать за верхнюю строку даже с F9.

## Возможности v1.2

- Чтение всего console.log с начала, затем новых строк. Совместное чтение,
  ротация, обрезание, неполные строки UTF-8 и защита повторного импорта.
- Подробные блоки CYBERSHOKE, исходные показатели, таблицы стрейфов,
  таймлайн клавиш/мыши и вывод jump_summary.
- Выбор старой попытки по ID, разбор с копированием текста, ручная аннотация
  направления и сравнение двух попыток.
- Ник в заголовке, колонке ИГРОК и разборе. Сохраняются регистр, Unicode
  и специальные символы. Длинные ники компактно сокращаются в таблице,
  полное имя остаётся в данных и копируемом тексте.
- Поддержаны суффиксы `[VNL]`, `[CKZ]`, `[KZT]`. LJ, BH и MBH не смешиваются.
  Имя относится к конкретной записи, не берётся из последнего найденного ника.
  Если имя неизвестно, выводится «Неизвестный игрок».
- `lj_history.dat` сохраняет попытки, имена, ID, отметки и исходные данные
  после перезапуска, в том числе при ротации или исчезновении старого лога.
- CSV в `lj_jumps/` содержит полный ник, `attempt_id`, показатели и отметки.
  Старые CSV не используются как источник и не переписываются.

## Порог успешности и персональная цель

INS -> 11 «Успех / персональная цель». Выберите тип прыжка и режим.
Настройки независимы для **LJ/BH/MBH/WJ/LAJ/JB × VNL/CKZ/KZT**.

Успешность: ранг Impressive..Wrecker либо своя дистанция, включая значения
выше Wrecker. Цель независима: следующий ранг, Wrecker по таблице выбранного
типа и режима, своя дистанция либо WR вручную. Ручной WR явно подписан
и не объявляется официальным мировым рекордом. Ранги CYBERSHOKE не меняются.

Минимум меняется кнопками минус/плюс с шагом 0.1u или точным вводом.
Свою цель и WR можно ввести отдельно. Enter применяет, Esc отменяет,
Ctrl+A очищает черновик, Ctrl+V вставляет. Принимаются точка и запятая.

Десятичные расчёты используют исходную строку дистанции:
256.0 - 255.9 = 0.1u. Достигнутая цель отображается зелёным.
Предупреждение Near Rank или цели появляется только при
`0 < остаток <= 0.50u`. Достигнутая цель не показывается как недостигнутая.

Смена порога пересчитывает автоматическую историю и текущий CSV.
Ручные отметки имеют приоритет, F8 возвращает авто.
Смена только цели не меняет GOOD/BAD и счётчики.

INI: секции `[jump_VNL_LJ]` и аналогичные; `success_mode`, `success_rank`,
`minimum`, `goal_mode=0..3`, `target`, `wr_manual`.
В `[overlay]` сохраняются тема, масштаб, прозрачность, видимость блоков,
число строк истории, положение, закрепление, путь к логу и фильтр `player`.

## Проверки и ограничения

Полная команда сборки:

```sh
g++ -std=c++20 -O2 -municode -mwindows -static -static-libgcc -static-libstdc++ lj_overlay.cpp -o LJOverlay_new.exe -lgdi32 -luser32 -lshell32 -ladvapi32 -lwinmm
```

Тесты: `powershell -NoProfile -ExecutionPolicy Bypass -File ./RUN_TESTS.ps1`.
Результаты тестов и временные данные создаются в игнорируемой папке `build/`.
См. [TESTING.md](TESTING.md), [VERIFICATION_RU.txt](VERIFICATION_RU.txt),
[FINAL_PUBLICATION_CHECK.txt](FINAL_PUBLICATION_CHECK.txt),
[CHANGELOG.md](CHANGELOG.md) и [скриншоты](screenshots/README.md).

Снимки получены реальной GDI-отрисовкой на синтетических данных.
LOG ERROR на отдельных снимках означает отсутствие игрового лога в стенде.
Физические нажатия при активной CS2, видимость поверх игры и слышимость
динамиков требуют ручной проверки. Неизвестные режимы и типы не угадываются.
Одинаковые безвременные блоки в разных позициях не склеиваются по дистанции:
лог не позволяет надёжно отличить копию от отдельной одинаковой попытки.

Готовый пакет Windows находится в Release v1.2. Исходники доступны в main.
Существующий Release v1.1 сохраняется.
